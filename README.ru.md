# hw-memory

[English version](README.md)

**hw-memory — это постоянная память для вашего агента.** Он запоминает решения, подводные камни, технический долг и открытые планы, которые команда обсуждает в чате, и возвращает их в следующей сессии — именно тогда, когда это важно. Никаких аккаунтов, облачной синхронизации и изменений в ваших документах без вашего одобрения.

- **Запоминает главное** — решения, подводные камни, технический долг, напоминания и записи changelog с ранжированием по важности.
- **Живёт вместе с проектом** — база данных лежит рядом с кодом и остаётся приватной для каждого расположения.
- **Документы — в ваших руках** — каждое обновление сначала предлагается, а записывается только после вашего одобрения.
- **Работает сам** — учится на выходных данных инструментов и из беседы, без ведения заметок вручную.

## Установка

Быстрая установка (macOS / Linux) загружает последний релиз и проверяет его контрольную сумму SHA256.

В текущий проект:

```sh
curl -fsSL https://raw.githubusercontent.com/hamsterwork/hw-memory/main/install.sh | bash
```

Глобально — одна установка на все проекты, но отдельная база данных для каждого:

```sh
curl -fsSL https://raw.githubusercontent.com/hamsterwork/hw-memory/main/install.sh | bash -s -- --global
```

Закрепите релиз через `--version vX.Y.Z`. Для независимой проверки задайте `HWM_SHA256=<hash>`. При несовпадении контрольной суммы установка останавливается, ничего не записывая.

Ручная установка из клона репозитория:

```sh
git clone https://github.com/hamsterwork/hw-memory.git
./hw-memory/install.sh /path/to/project      # установка в проект
./hw-memory/install.sh --global              # глобальная установка
```

Установщик помещает плагин в `.opencode/plugins/` и добавляет правила использования в `AGENTS.md` проекта (или в `CLAUDE.md`, если это активный файл правил) между специальными маркерами. Повторный запуск обновляет этот блок на месте. После установки перезапустите opencode.

## Обновление

`update.sh` определяет установленную версию, сравнивает её с последним релизом GitHub и с вашего подтверждения устанавливает проверенный релиз, сохраняя `.bak` предыдущего плагина.

```sh
# установка в проекте (запускать из корня проекта)
curl -fsSL https://raw.githubusercontent.com/hamsterwork/hw-memory/main/update.sh | bash

# глобальная установка
curl -fsSL .../update.sh | bash -s -- --global

# только проверка — без изменений, код выхода 1, если доступно обновление
curl -fsSL .../update.sh | bash -s -- --check
```

Из клона: `./update.sh [target-dir]`, `./update.sh --global` или `npm run update`. Флаги: `--version vX.Y.Z`, `--base-url`, `--no-rules`, `--yes` (неинтерактивный режим) и `--check`. Блок правил обновляется, если не указан `--no-rules`; загрузка проверяется до того, как что-либо будет записано.

## Использование

Один раз импортируйте файл или папку, затем работайте как обычно. Агент при необходимости вспоминает сохранённые факты, добавляет новые и предлагает обновления документации на ваше рассмотрение.

### Команды

| Команда | Назначение |
|---|---|
| `/hw-seed <path> [--apply] [--changed]` | Сидирование файла или папки; сначала пробный запуск |
| `/hw-docs [--apply] [--id N]` | Просмотр и запись предложенных обновлений документации; отчёт о дрейфе |
| `/hw-changes [version] [--source git\|journal] [--ai] [--export]` | Список изменений и экспорт changelog |
| `/hw-dashboard [--prune]` | Долги, напоминания, предложения очистки, обновления документации |
| `/hw-debts` | Список открытого долга и его возраст |
| `/hw-reminders` | Список напоминаний, планов и открытых вопросов |

Отчёты детерминированы; модель вызывается только для `/hw-changes --ai`.

### Инструменты

`hw_memory_add`, `hw_memory_search`, `hw_memory_stats`, `hw_memory_forget`, `hw_memory_debt` (список, проверка и разрешение долга), `hw_memory_reminder` (список, проверка и разрешение напоминаний) и `hw_memory_config` (настройки). Просто попросите агента что-то запомнить, вспомнить или изменить — он выберет нужный инструмент.

### Настройки

Попросите агента изменить настройку через `hw_memory_config` или дайте прямую инструкцию, например «хранить не более 1000 фактов» или «использовать историю git для changelog».

| Настройка | Значения | Что делает |
|---|---|---|
| `cap_rows` | 50..100000, по умолчанию 500 | Максимум фактов на проект; уменьшение применяется сразу |
| `changelog.source` | `auto`, `git`, `journal` | Источник истории для `/hw-changes` (`auto` использует git, если доступен) |
| `changelog.summary` | `deterministic`, `ai` | Стиль краткого описания (`ai` обращается к модели при `/hw-changes --ai`) |
| `decision` / `gotcha` / `debt` / `reminder` / `changelog` | `enabled` / `disabled`, по умолчанию отключено | Экспортировать ли этот вид в `docs/hw-memory/` |

Управляемые файлы записываются только при `/hw-docs --apply`. Чтобы отключить экспорт вида, установите его в `disabled` через `hw_memory_config`.

### Ваши данные

Каждое расположение хранит свою базу по адресу `.opencode/hw-memory.db`. Установщик добавляет её (и сопутствующие файлы) в `.gitignore`. Включённые управляемые экспорты находятся в `docs/hw-memory/`.

## Безопасность

hw-memory никогда не перезаписывает ваш текст в документах, не записывает документ без `/hw-docs --apply` и не сидирует файл без явного `/hw-seed <path>`. Он сохраняет важные факты по умолчанию и предлагает очистку только для спорных, которые вы подтверждаете через `/hw-dashboard --prune`.

## Расширенное использование

### Сидирование по области

`/hw-seed <path>` читает один файл (без ограничения размера) или папку (по умолчанию 200 файлов / 1 МиБ на файл / глубина 8). Сначала выводится пробный отчёт, `--apply` сохраняет результат. Пункты классифицируются по маркерам вида `[decision]`, `[gotcha]`, `TODO:` или по эвристикам ключевых слов — на английском и русском (`[решение]`, `[долг]`, `вопрос:` и их ключевые слова). Факты, исчезнувшие из сидированной области, понижаются в ранге, а не удаляются молча. После правки сидированного файла дрейф сообщается при простое, а `/hw-seed <path> --apply` пересинхронизирует эту область.

### Управляемые документы

Для каждого включённого вида новые факты попадают в очередь предложений. `/hw-docs` показывает, что будет записано или удалено; `/hw-docs --apply` записывает только созданные плагином строки безопасным построчным модулем и оставляет ваш текст нетронутым. Разрешение долга или напоминания через `hw_memory_debt` / `hw_memory_reminder` убирает его из списка открытых; строка в документе удаляется при следующем `/hw-docs --apply`.

### Открытые пункты: долг и напоминания

Долг и напоминания не исчезают сами, поэтому у них есть не срок жизни, а решение. **Долг — это сознательно принятая цена, которая растёт, пока пункт открыт**: в коде (обходной путь, отсутствующий тест, расхождение API), в управлении (ручная сверка, один показатель считается по-разному в двух отчётах, шаг, который умеет делать только один человек) и в исследованиях (набор данных без провенанса и версии, невоспроизводимый анализ, устаревший источник). Напоминание — это работа, которую просто нужно сделать. Если игнорирование дорожает — это долг; если просто нужно сделать — напоминание. Решают два действия:

- `action: verify` фиксирует, что пункт проверен и всё ещё актуален. Меняется только дата проверки — вес и таймер затухания не трогаются, поэтому повторная проверка не может держать пункт живым вечно.
- `action: resolve` помечает пункт выполненным. Он исчезает из всех списков, а его строка в управляемом документе удаляется при следующем `/hw-docs --apply`.

Списки (`hw_memory_debt`, `hw_memory_reminder`, `/hw-debts`, `/hw-reminders`) показывают возраст в виде `open 41d, checked 18d ago`, а контекст пробуждения подмешивает только пункты, похожие на текущую задачу. Когда задача завершается фразой вроде «готово» или «done», ограниченная проверка называет не более пяти неразобранных id; фоновая проверка охватывает пункты, не проверявшиеся неделю и более. Каждый пункт повторяется не чаще раза в сутки, а проверенный сегодня не повторяется вовсе.

### Changelog

`/hw-changes [version]` формирует понятный список изменений из истории git (`[tag]..HEAD`) или записанных событий журнала. `--export` записывает его в `docs/hw-memory/changelog.md`.

### Хранение фактов

Факты теряют вес с возрастом и при редком использовании, но важные сохраняются: ничего `critical` не удаляется, `high` защищены до пометки устаревшими, а `debt`, `reminder` и `changelog` никогда не очищаются и не ограничиваются по количеству. `medium` решения и подводные камни очищаются только после вашего одобрения; `low` временные факты убираются незаметно.
